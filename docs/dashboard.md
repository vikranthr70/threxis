# THREXIS forensic research workstation

Status: local academic demonstration. **NOT READY FOR PUBLIC LAUNCH**.

## Run locally

From the repository checkout:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Open http://127.0.0.1:8501. The supplied configuration binds the server to loopback, disables Streamlit usage statistics, and serves bundled IBM Plex fonts locally. Do not expose this development server publicly.

This dashboard branch builds on `integration/person1-person2-upgrade`, which provides the required contributor modules. No experiment runner is added here.

## Pages and data flow

- Command Center: readiness instrument and actual event, alert, mapping, and unknown-source counts.
- Forensic Readiness: source contributions, status factors, gaps, recommendations, hypothetical simulation, accessible data table, and explicitly labelled scenario macro average.
- Threat Detection: actual backend alerts, severity filtering, supported ATT&CK candidates, and normalized synthetic records.
- Evidence Prioritization: artifact availability inputs, fixed budgets, all five comparison strategies, candidate ledger, adaptive ranking details, and JSON download.
- Incident Investigation: filterable chronological timeline, correlations, missing-preservation coverage, case JSON and Markdown downloads.
- Evidence Vault: preserve selected synthetic records, recalculate SHA-256, view collection/verification audits, and export a ZIP.
- Research Evaluation: schema-validated user-supplied EvaluationResult JSONL. No research metrics or charts are manufactured when saved results are absent.
- Privacy Policy, Terms and Conditions, and Launch Status: working navigation to review drafts and incomplete release requirements.

`src.ui.service` orchestrates the existing generators, readiness assessment, availability adapter, selection comparison, ATT&CK mapping, correlation, vault, timeline, and reporting functions. It discards generated ground-truth labels before the operational workflow. Streamlit does not reimplement those algorithms.

## Scoring and scenario state

Readiness factors are unchanged: available 0.60, collected 0.85, validated 1.00, missing/unknown 0.00, and not-applicable excluded from the denominator. Contributions and gaps come directly from the backend. The segmented instrument represents five percentage points per segment and has a text/table equivalent. The displayed exact score is authoritative.

Unobserved requirements stay unknown. Explicitly excluded artifacts become unavailable, and a source with no eligible artifact becomes missing. Source presence does not establish completeness. No source is marked validated merely because its hash verifies.

The sidebar changes scenario, seed, and event count. Readiness, recommendations, candidates, alerts, and timelines are rebuilt from the current instance. Artifact exclusions are scoped by scenario/seed/count. Budget and exclusion preferences survive page navigation. Workspace changes clear preserved evidence and previous verification results. Simulation uses separate inputs and never mutates current observations.

Preserved artifacts live in a server-side temporary directory and are explicitly exportable. Normal workspace changes clean the directory. Session release and process termination govern eventual cleanup; a crash may leave temporary files. The server has no production authentication or retention system.

## Design and accessibility

Centralized tokens use graphite, warm ivory, muted teal, and oxide red. Controls and panels have rectangular geometry, maximum 2px radius, 1px borders, and no gradients or shadows. Bundled IBM Plex Sans and Mono include the SIL Open Font License. An original T mark represents three evidence tracks joined by a central spine; it is generated by `src.ui.theme.favicon` and supplied to Streamlit as the page icon.

All input controls retain native Streamlit labels and keyboard behavior. Status text accompanies color, focus outlines are explicit, reduced-motion preferences are respected, and the custom instrument has an accessible textual equivalent. CSS includes a narrow-screen breakpoint. Actual browser visual inspection is still required.
